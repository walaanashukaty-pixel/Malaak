# Malaak Android Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Flutter source Android-release-ready by hardening keyboard/safe-area/navigation behavior, adding reproducible Android scaffolding/build automation, and extending release verification without changing Malaak's approved Figma visual identity.

**Architecture:** Keep the Flutter UI and Supabase architecture unchanged. Add a small mobile-layout utility for keyboard-aware bottom spacing, hide the floating bottom navigation while the keyboard is open, make chat input resilient to IME insets, and add reproducible Android bootstrap plus CI/build scripts. Because Flutter/Android SDK is unavailable in this environment, executable Python/Node structure checks gate the source here, while Flutter widget/analyze/build commands are included for CI and the user's Android environment.

**Tech Stack:** Flutter/Dart, Supabase Flutter, Python 3 structural verifiers, GitHub Actions, Android Gradle scaffold generated by the installed Flutter stable channel.

**Spec:** `docs/superpowers/specs/2026-08-29-malaak-scientific-library-formulation-v5-design.md`

## Global Constraints

- Preserve Arabic RTL and the approved Figma visual palette/layout language.
- No Sidebar or Drawer; Home remains the application hub and bottom navigation remains four tabs.
- Do not embed `OPENAI_API_KEY` or Supabase service-role secrets in Flutter or Android client files.
- Android package id: `com.malaak.malaak_balance`.
- Android display name: `ملاك`.
- Android scaffold must be generated reproducibly with the installed Flutter stable toolchain, not handwritten Gradle templates.
- Existing V5 release verification must remain green.
